## 真机验证记录

### 2026-08-24：远程词库首次更新、304 与热更新验证

- 本地测试构建注入固定地址 `https://raw.githubusercontent.com/mangataw/SteamGameName/main/data/translations.zh-CN.json`，未开放用户自定义 URL。
- 首次启动自动取得 76 条远程词库并写入 `catalog.json` 与 `metadata.json`；状态为“最新”，来源为 `remote`。
- 手动刷新在远程内容未变化时保持 ETag、条目数和最后成功更新时间不变，仅更新上次检查时间，符合 304 行为。
- 真机发现 Lua `on_frontend_loaded` 在当前 Millennium 启动顺序下未可靠触发；自动检查已改由前端初始化完成后以 `force=false` 主动调用，重启后无需手动操作即可更新上次检查时间并进入“最新”状态。
- 缓存内容经 304 确认后仍以缓存作为物理数据来源；设置页将状态显示为“最新（已联网确认）”，来源保持简短的“缓存”，避免误认为没有联网检查并防止窄设置页换行。
- 向远程词库加入 AppID `779340`“全面战争：三国”和 AppID `761620`“旁观者 2”后，不重启 Steam 手动刷新，条目数从 76 增至 78，ETag 与成功更新时间同步更新。
- 用户真机确认 `Beholder 2` 在当前双语模式下立即显示为 `旁观者 2 | Beholder 2`。
- GitHub Raw 主分支更新存在短暂 CDN 传播延迟；等待主 URL 返回新 ETag 后刷新成功，不影响旧缓存继续使用。

### 2026-08-24：远程超时与缓存回退验证

- 使用只改变编译时远程地址的专用测试包，将请求指向不可响应端点；内置词库、缓存代码和前端逻辑均保持正式版本一致。

- 完整重启 Steam 后仍从 `cache` 加载 78 条词库，Beholder 2 名称正常，确认缓存可以跨会话保留。
- 测试期间发现 Millennium 将旧 `%STEAM%\ext` 搬入 `millennium-migration-temp`；恢复缓存后再次重启未重复迁移，判定为一次性 Millennium 目录迁移，而非插件持续性缓存路径故障。

### 2026-08-24：`v0.1.7` 显示模式修复自动化验证

- 配置界面只保留“双语”和“仅中文”，不再使用在 Steam 设置页中选择无效的原生 HTML `select`。
- 后端只接受两种模式，并将历史 `original` 配置持久迁移为默认 `bilingual`。
- 设置持久化成功后，前端存储会原子发布新快照；失败时保持现状并显示错误。
- 前端兼容 RPC 返回 JSON 字符串或已解码对象，避免重复 `JSON.parse` 导致设置、词库和状态快照全部加载失败。
- RPC JSON 使用 ASCII-only Unicode 转义跨越 FFI，状态和错误使用稳定代码并由前端本地化，避免中文乱码。
- 显示模式控件改为独占下一行的宽布局，选项缩短为“双语”和“仅中文”，完整格式放在说明文字中。
- 左栏补丁从一次性字符串格式化改为挂载订阅前端存储的响应式组件，同时保留启动回退与长度门禁。

### 2026-08-24：`v0.1.4` 扩充词库后 SteamUI 无法启动

- 环境：Windows，Steam 桌面客户端，Millennium `v3.4.1`。
- 现象：Steam 更新/验证窗口关闭后主窗口不出现，独立推广窗口也随 Steam Web UI 一起消失；`steam.exe` 和 Millennium 后端存活，但没有 `steamwebhelper.exe`。
- 隔离：禁用插件后 Steam 正常启动，重新启用 `v0.1.4` 后问题复现。
- 定位：完整 70 条词库被复制进 Hooking API 替换字符串；自动化 fixture 能验证 JavaScript 语法，但不能覆盖 Millennium/SteamUI 对长替换的运行时兼容性。
- `v0.1.5` 处理：完整词库移至前端初始快照与后端资源，补丁只保留不超过 8 条、编码后小于 1 KiB 的固定启动回退；真机启用后 SteamUI 正常启动，新增中文名正常显示。

### 2026-08-24：`v0.1.0` 发布包未出现在插件列表

- 环境：Windows，Steam 桌面客户端，Millennium `v3.4.1`。
- 现象：将发布 ZIP 解压到本机实际插件目录后，Millennium 插件列表仍为空。
- 定位：ZIP 内只有无扩展名的 `steam-game-name-zh`；该文件本身可通过 Starlight v2 四区段校验，但 Millennium 只识别 `.star` 插件包。
- 临时规避：将文件重命名为 `steam-game-name-zh.star` 后重新启动 Steam。
- 下版本验收：正式构建直接生成 `.star` 文件；ZIP 保留该扩展名；自动化检查归档条目名并运行 `starlight verify`；在干净的 Millennium `v3.4.1` 环境解压、重启后，插件列表能够显示“Steam 游戏名中文化”。
