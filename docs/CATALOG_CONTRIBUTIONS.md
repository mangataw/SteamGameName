# 词库建议与贡献

`data/translations.zh-CN.json` 是按 Steam AppID 维护的简体中文显示映射。它只处理 Steam 当前名称不含汉字的游戏，不修改 Steam 数据，也不代表发行商官方本地化。

## 普通用户：提交 Issue

如果只是希望补充或纠正一个游戏名称，请使用“词库建议”Issue 模板，不需要修改 JSON、运行测试或了解项目构建流程。

每条建议只需提供：

1. 改动类型：新增、修正或删除；
2. Steam AppID；
3. Steam 当前原名；
4. 建议简体中文名。

标题以模板自动填入的 `[词库]` 开头，后面写游戏名称，例如：

```text
[词库] Portal 2 / 传送门 2
```

如果是修正或删除，可以在可选的“补充说明”中写明当前词库名称和原因；有官方页面、发行商用名或社区常用译名链接时也可以附上，但这不是提交 Issue 的前提。作者会在更新词库前核对 AppID、Steam 当前名称、游戏类型、版本后缀和译名依据。

一个 Issue 建议只提交一个游戏，方便核对、讨论和关闭。批量建议可以先开一个 Issue 说明范围，由作者决定是否拆分。

不要在公开 Issue 中填写 Steam ID、账户信息、Cookie、令牌、私人游戏库数据或完整本地路径。安全漏洞请按 [安全政策](../SECURITY.md) 私下报告。

## 开发者：提交 PR

PR 面向已经实际修改仓库文件的开发者或贡献者。PR 需要说明变更范围，并负责保持文件格式、排序、测试和仓库门禁通过。

只修改词库时，PR 至少应包含：

- 新增、修正或删除的 AppID；
- Steam 当前原名；
- 修改前后的中文名；
- 来源链接或选择理由；
- `pnpm run check` 的通过结果。

词库 PR 应只包含词库及直接相关说明，不要混入 Hook 补丁、构建配置、远程地址或无关格式化。代码 PR 则应说明问题、实现边界、测试范围，以及需要的真机验证结果。

## 作者审核规则

作者合入 Issue 或审核 PR 时按以下顺序选择名称：

1. Steam 当前官方简体中文名称；
2. 发行商或开发者使用的简体中文名称；
3. 可靠中文社区长期一致使用、无歧义的常用译名；
4. 无法形成稳定结论时不收录，保留 Steam 原名。

以下内容不收录：

- Steam 当前名称已经含有汉字的冗余映射；
- 只为提高覆盖率而创造的译名或未经核对的机器直译；
- 广告语、评价、攻略提示、表情、HTML、控制字符或与标题无关的说明；
- 无法唯一对应 AppID 的名称；
- 工具、软件、原声、专用服务器和非 Steam 快捷方式。

## 示例

### 简单有效的 Issue

```text
标题：[词库] Portal 2 / 传送门 2
改动类型：新增映射
Steam AppID：620
Steam 当前原名：Portal 2
建议简体中文名：传送门 2
补充说明：（可留空）
```

### 需要补充的 Issue

```text
标题：加个中文名
Steam AppID：（空）
Steam 当前原名：Portal
建议简体中文名：传送门
```

缺少 AppID 时无法唯一确认游戏，作者会请提交者补充。

### 不应提交的建议

- 为 Steam 当前已经显示中文的游戏重复添加相同映射；
- 将 `Some Game` 直接机器翻译为“某个游戏”，没有稳定用法；
- 把“年度最佳、现在购买！”等营销文字加入标题。

## PR 修改与验证

词库文件必须保持 UTF-8、无 BOM，并按 AppID 数值升序。完成仓库修改后运行：

```powershell
pnpm install --frozen-lockfile
pnpm run check
```

`pnpm run check` 会校验 Schema、AppID、排序、汉字、重复键、HTML/控制字符、自动化测试和仓库公开性门禁。不要提交 `.star`、ZIP、缓存或其他生成文件。
